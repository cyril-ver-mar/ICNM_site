## Одна фраза, с которой начинать

> Новый сайт института — WordPress, как у ИБОХ: PHP 8.3 и MySQL, не Java. На текущий Java-контур его ставить нельзя. Нам нужен **параллельный тестовый адрес**, полный **снимок DNS и почты**, архив старого сайта и письменная **процедура переключения** `ichnm.by`, чтобы почта и `aist.ichnm.by` не отвалились.

Так вы сразу выглядите как человек, который понимает разницу между «залить файлы» и «переключить домен».

## Памятка 1. Четыре разные вещи (их часто путают)

| Что | Простыми словами | Кто может владеть |
| --- | --- | --- |
| **Домен** `ichnm.by` | Имя. Арендуется у регистратора. | Часто Active.by; логин может быть у института **или** у Forever |
| **DNS** | Таблица: имя → IP, почта, поддомены | Обычно панель того же регистратора |
| **Хостинг сайта** | Компьютер, где крутится страница | Сейчас Java на IP Hoster.by; новый сайт — **другой** PHP-тариф |
| **Почта** `@ichnm.by` | Письма. Живёт по записям **MX**, не «внутри сайта» | Сейчас g-cloud.by; **не должна** поехать вместе с сайтом |

Бесшовно = поменять **только** запись, которая ведёт **сайт** (`A` / `AAAA` / иногда `CNAME` для `www`), не трогая MX и поддомены, которые должны остаться.

**Нельзя:** «залить WordPress по FTP на Java-сервер Forever». WordPress — это PHP-скрипты + база MySQL. Java-сервер их не исполняет. Даже если Forever даст «доступ на заливку», спросите: *это PHP 8 + MySQL или тот же Java?* Если Java — вежливо отказаться и просить PHP-площадку **рядом**, не вместо старого сайта.

## Памятка 2. Как открывается сайт (30 секунд)

1. Человек вводит `ichnm.by`.
2. Компьютер спрашивает DNS: «какой IP?»
3. Браузер идёт на этот IP и просит страницу. Сейчас там nginx + Java Forever.
4. После переключения тот же вопрос DNS должен ответить **другим IP** — PHP-хостингом с WordPress.

Пока DNS не сменили, новый WordPress может жить на адресе вроде `new.ichnm.by` или `xxx.hoster.by`. Старый `ichnm.by` при этом **не должен** сломаться.

**TTL** — сколько минут интернет помнит старый IP. Перед переключением TTL снижают (например до 300 секунд), чтобы откат занял минуты, а не сутки.

---

## Памятка 3. Что должно остаться нетронутым

- Почта `@ichnm.by` (MX, SPF, DKIM, DMARC).
- `aist.ichnm.by` — регистрация конференции.
- Любые другие поддомены, о которых вы ещё не знаете (`mail.`, `webmail.`, `ftp.`, `www.`).
- Старый сайт до приказа директора: его не удаляют в день «доступа».

---

## Памятка 4. Слова, которые можно произносить спокойно

- **A-запись** — «на какой IP указывает имя».
- **MX** — «куда слать почту».
- **CNAME** — «это имя — синоним другого имени» (часто `www` → `ichnm.by`).
- **TXT** — служебные пометки: подтверждение Яндекса/Google, SPF почты.
- **SSL / HTTPS** — сертификат замка в браузере. На новом IP его выпускают заново (часто Let’s Encrypt).
- **Панель** — сайт хостера, где сайты, базы, почта, DNS (часто ISPmanager).
- **SFTP / SSH** — нормальный доступ к файлам. Обычный FTP без шифрования — хуже, но встречается.
- **PHP-тариф** — обычный белорусский хостинг под WordPress (Active.by или Hoster.by), не «Java-хостинг Forever».
- **Тестовый URL** — адрес, по которому руководство смотрит новый сайт **до** смены `ichnm.by`.
- **Откат** — вернуть A-запись на старый IP, если в день переключения что-то пошло не так.

Цифры, которые можно назвать, если спросят «какие требования»: PHP **8.2 или 8.3**, MariaDB 10.6+ или MySQL 8, HTTPS, `memory_limit` ≥ 256M, загрузка файлов ≥ 64M, `max_input_vars` ≥ 3000 (большие меню Kadence). Это обычный WordPress-хостинг, не выделенный сервер.

### 2. Полный снимок DNS (самое важное вложение)

9. **Экспорт зоны** `ichnm.by`: все NS, A, AAAA, CNAME, MX, TXT, SRV, CAA. Не «основные», а **все**.
10. Список **всех поддоменов**, которые резолвятся или когда-либо использовались: `www`, `aist`, `mail`, `webmail`, `ftp`, `cpanel`, тестовые имена, старые CMS.

14. Где ящики `@ichnm.by`: g-cloud.by или ещё где? URL веб-почты.
15. Записи MX, SPF, DKIM, DMARC — в экспорте зоны и расшифровка «не удалять».
16. Шлёт ли **старый сайт** письма (формы, уведомления)? С какого адреса и через какой SMTP?

### 4. Старый сайт: архив, URL, формы
